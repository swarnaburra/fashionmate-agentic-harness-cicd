# ADR-001: Convert citation list assembly from agent to deterministic code

## Status
Proposed

## Context

Every role in the orchestration ends by emitting an output document with `summary` and `citation_list`. Today the model writes `citation_list` itself, following one instruction in `_FINALIZE_INSTRUCTIONS` (`eval/orchestrator.py`, line 385): *"For roles using retrieve, list the source_document names in citation_list."* That is a lookup over data the orchestrator already holds, the role's own `retrieve` results, not a judgment. `docs/step-classification.md` marks it the only strong candidate on all four signals. Measured across 122 role outputs in the committed transcripts, the agent matched that rule exactly in 84 (68.9%). The other 38 were spec violations: wrong order (12), storage entry IDs cited as documents (9), real documents cited by a role that made no `retrieve` call (8), paraphrased or invented names (5), and a missing field (4). On the default development task run 7 times, the tester wrote 5 different lists although its own retrievals justify 1. This step also produced one of the six Module 3 failure modes (schema validation: `citations` instead of `citation_list`), which was patched with stricter prompt wording rather than removed. The edge cases the deterministic version must handle deliberately are named in the classification: a role that relied on documents passed down in its handoff without retrieving them itself, and a role that cited storage entries it read.

## Decision
Replace the agent-written `citation_list` with a deterministic function in the orchestrator that sets each role's `citation_list` to the unique `source_document` values from that role's own `retrieve` results in the current run, in order of first appearance (`[]` if it made no `retrieve` call), overwriting any value the model produced, and remove the citation instruction from the prompt.

## Alternatives considered

- **Keep the agentic step (status quo).** Rejected. The agent is correct only 68.9% of the time on a task with one correct answer per transcript, and its errors are the kind that matter for an audit trail: 5 citations name documents that do not exist under those names, and 9 cite storage entries as if they were source documents. The flexibility of a model is unused here: under the rule, the agent never once omitted a document it had retrieved (0 of 122), so it did not exercise any relevance judgment worth keeping.
- **Tighten the prompt further (stricter wording, few-shot examples, a smaller model).** Rejected. This is the approach already tried: Module 3 fix 2e31057 added an explicit contract line after the `citations` / `citation_list` failure. Deviations continued after it; for example, in REGRESSION-default (run after all Module 3 fixes) the tester cited a storage entry ID (`f9293821-...`) instead of `[]`. A better prompt can lower the error rate but cannot make a model's output repeatable, and it keeps governance and evaluation overhead on a structural step.
- **Keep the agent but add a deterministic validator that rejects a wrong list and retries.** Rejected. To know a list is wrong, the validator must compute the correct list; once it has, asking the model to reproduce it adds a retry, extra tokens, extra latency and a new failure path for no benefit. Computing the value directly is strictly simpler.
- **Convert, but inherit citations from the previous role (Rule B: own retrievals plus the upstream list).** Rejected. It matched the agent only 59 of 122 times (48.4%), so it does not describe what the agent actually did; it is not what the written spec says; and it would copy any upstream mistake into every later role. Upstream provenance already travels in the scoped handoff chain, so nothing is lost by keeping `citation_list` to what each role itself retrieved.
- **Convert to deterministic code (Rule A).** Preferred. Expected to produce the correct list for every output, identical across runs for the same tool calls, with no added model call. Quality bar before integration: (1) unit tests covering the named edge cases: no `retrieve` call gives `[]`; duplicate results across several `retrieve` calls appear once; order is first appearance; documents withheld by the classification ceiling never appear (they are never returned); storage reads (`read_entry`, `list_entries`) do not appear; a model-supplied `citation_list`, wrong or missing, is overwritten; (2) replaying the rule over all committed transcripts yields a valid list for every one of the 122 outputs; (3) every deterministic harness check the current workflow passes still passes, with no regression. Acceptance waits until the function is integrated into the running orchestrator and an end-to-end regression run of the default development task passes with no new failures.

## Consequences

Expected benefits: every citation is verifiable, because it can only name a document the role actually retrieved; output is perfectly repeatable for the same tool calls; the Module 3 "schema validation" failure mode is removed by design instead of by prompt wording; the harness can check citations exactly instead of only checking that the field exists; and a reviewer can understand the step by reading a few lines of code. Token and latency savings are expected to be small, because the list is produced inside the same model call as the summary; the case for conversion is correctness and repeatability, not cost.

Known trade-offs: the agent's occasional carrying-forward of upstream citations (8 outputs) is dropped from `citation_list`. If the team later wants explicit upstream provenance, it should be a separate deterministic field (for example `inherited_citations`), not a return to the agent. If retrieval semantics change (for example, roles start using only part of what they retrieve, and "cited" should mean "used"), the rule must be revisited, and that judgment might belong back with an agent.

To watch before integration: the unit tests and the transcript replay pass; the 14 deterministic checks still pass. To accept the ADR later: the integrated orchestrator passes an end-to-end regression run with no new failures, citation correctness measured by `scripts/analyze_citations.py` on the new transcripts is 100%, the rubric's groundedness score does not drop, and `docs/routing-and-tool-grant-map.json`, the governance policy and `docs/ci-step-design.md` stay consistent.
